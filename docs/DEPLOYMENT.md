# Deploying FairShare

FairShare runs as **one Render web service** (Express serves the API and the built React app) with a **MongoDB
Atlas** database. Both have free tiers; this guide uses only those and needs no payment card.

Allow about 30 minutes. Screens change over time, so button names may differ slightly from what is written here.

**Free-tier facts to know before you start**
- Render free services sleep after 15 minutes without visitors. The next visit waits about a minute while the
  service wakes up. Each account gets 750 free instance hours per month.
- The Atlas free cluster holds 0.5 GB of data, allows one free cluster per project, and pauses after 30 days with no
  connections at all.

---

## Part 1: MongoDB Atlas (the database)

### 1. Create the account and the cluster
1. Go to https://www.mongodb.com/cloud/atlas/register and sign up (Google sign-in is fine).
2. When Atlas offers to create a cluster (or on the **Clusters** page, click **Create**), choose the **Free** option.
3. Provider: **AWS**. Region: **Singapore (ap-southeast-1)** if it is offered for the free tier, otherwise
   **Mumbai (ap-south-1)**. Singapore matches the Render region in `render.yaml`, which keeps the app and the
   database close together.
4. Cluster name: leave `Cluster0` or call it `fairshare`. Untick any option to load sample data. Click the create
   button and wait a few minutes until the cluster shows as active.

### 2. Create the database user
Atlas may ask for this straight after creating the cluster. Otherwise go to **Database & Network Access** (under
**Security** in the sidebar) → **Database Users** → **Add New Database User**.

1. Authentication: **Password**. Username: `fairshare-app`.
2. Click **Autogenerate Secure Password**, then **Copy**, and keep the password somewhere safe (a password manager).
   An autogenerated password has no special characters, so it can go straight into the connection string.
3. Role: **Read and write to any database** (or the default role Atlas suggests for your first user).
4. Click **Add User** / **Create Database User**.

### 3. Allow Render to connect
Go to **Database & Network Access** → **IP Access List** → **Add IP Address**.

- Enter `0.0.0.0/0` (some screens have an **Allow Access from Anywhere** button for this), add the comment
  `Render`, and click **Confirm**.
- Why: Render's free services don't have one fixed address. Atlas will email you a warning about `0.0.0.0/0`.
  That's expected: the database is still protected by the user's long random password. Part 3 shows how to narrow
  this down once the Render service exists.

### 4. Copy the connection string
1. Go to **Clusters** → click **Connect** on your cluster → **Drivers** → choose **Node.js**.
2. Copy the connection string. It looks like:
   ```
   mongodb+srv://fairshare-app:<db_password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```
3. Make two changes (in a plain text editor, not in any file inside the project):
   - Replace `<db_password>` (including the `<` and `>`) with the password from step 2.
   - Add the database name **`fairshare`** right after `.mongodb.net/` and before the `?`:
     ```
     mongodb+srv://fairshare-app:YOUR_PASSWORD@cluster0.abcde.mongodb.net/fairshare?retryWrites=true&w=majority&appName=Cluster0
     ```
     Without it, MongoDB stores everything in a database called `test`.

Never commit this string or paste it into chat, an issue or a screenshot. It only goes into Render (Part 2).

## Part 2: Render (the app)

### 5. Create the account
Go to https://dashboard.render.com and sign up **with GitHub**, so Render can see your repositories.

### 6. Create the service from the Blueprint
1. In the Render Dashboard, click **New** → **Blueprint**.
2. If asked, connect your GitHub account and allow access to the `fairshare` repository (all repositories, or just
   this one). Then click **Connect** next to `manishguptha188/fairshare`.
3. Blueprint name: `fairshare`. Branch: `main`. Leave **Blueprint Path** as `render.yaml`.
4. Render lists what it will create: one web service called `fairshare` (free plan, Singapore). It asks for a value
   for **`MONGODB_URI`**: paste the full connection string from step 4.
   `JWT_SECRET` is generated by Render automatically; you don't need to type one.
5. Click **Deploy Blueprint**.

### 7. Watch the first deploy
Open the `fairshare` service and its **Logs**. The build installs packages and builds the React app
(a few minutes), then you should see:
```
FairShare API listening on http://localhost:10000
```
(Render picks the port itself; the app reads it from `PORT`.) When the status says **Live**, open the URL at the
top of the page, something like `https://fairshare-xxxx.onrender.com`.

### 8. Check it works
1. Open `https://YOUR-URL/api/health`. It should show `{"status":"ok"}`.
2. Open `https://YOUR-URL`, create an account, create a group and add an expense.
3. Reload the page: you should still be logged in (the cookie is `Secure`, which works because Render serves HTTPS).

From now on, every push to `main` redeploys the app automatically.

## Part 3: Optional improvements

### Narrow the Atlas access list
On the Render service page, open **Connect** (top right) → **Outbound**. Render lists the address ranges its
Singapore services use. In Atlas, add each range under **IP Access List** → **Add IP Address**, check the app still
works, then delete the `0.0.0.0/0` entry.

### Add the demo accounts
Recruiters can try the app without signing up if the sample accounts exist. They are public (everyone can see the
password in the README) and anyone can change their data, so treat them as a sandbox. To add or reset them, run this
**in PowerShell on your own computer**, from the `fairshare` folder, with your real connection string:

```powershell
$env:MONGODB_URI = "mongodb+srv://fairshare-app:YOUR_PASSWORD@cluster0.abcde.mongodb.net/fairshare?retryWrites=true&w=majority"
npm run seed
Remove-Item Env:MONGODB_URI
```

The last line removes the connection string from that PowerShell window. The seed script only replaces the three
`example.com` sample accounts and their group; other people's accounts are left alone.

### Show the live link
- On GitHub, open the repository's **About** settings (the gear next to "About") and paste the Render URL into
  **Website**.
- Add the link to the top of `README.md`.

## If something goes wrong

| What you see | Likely cause and fix |
|---|---|
| Logs say `Could not connect to MongoDB` or `querySrv ENOTFOUND` | The connection string is wrong. In Render, open the service → **Environment**, fix `MONGODB_URI`, save (it redeploys). |
| `bad auth : authentication failed` | The password in the string doesn't match the database user. Reset it in Atlas (Database Users → Edit) and update `MONGODB_URI`. |
| `connection ... timed out` / `Server selection timed out` | Atlas is blocking Render. Check that the IP Access List has `0.0.0.0/0` or Render's outbound ranges. |
| Build fails at `vite: not found` | The build command lost `--include=dev`; it must be `npm ci --include=dev && npm run build`. |
| The first visit takes about a minute | Normal on the free plan: the service was asleep. |
| Data is in a database called `test` | The connection string is missing `/fairshare` before the `?`. Fix it and redeploy; recreate any accounts. |
